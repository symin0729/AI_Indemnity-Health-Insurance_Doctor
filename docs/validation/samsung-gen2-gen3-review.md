# 1611.7 잔여 수정 및 1704.1 규칙 검산

이 문서는 구현 검토 기록이며 RAG 입력이나 운영 RuleSet이 아니다. 실제 저장소 PDF를 PDFKit으로 추출하여 조항을 확인했다. 17번 설계서는 Downloads의 `17_generation_1_to_5_user_selection_and_rule_engine_input_guide.md`를 읽었으며 숫자/산식의 출처로 사용하지 않았다. 1·4·5세대 계산 동작 및 UI/API는 이번 변경 대상이 아니다.

## 1611.7 C05 및 숫자 검증

- PDF 48쪽 제3조 (1)⑤, 53쪽 (3)⑥, 선택형Ⅱ 106쪽 (1)⑤·112쪽 (3)⑥: 종료 시 계속 중인 입원은 종료일을 제외한 180일까지. 한도 복원 제4항은 적용하지 않는다. 자동갱신 또는 동일 회사 재가입은 보험기간 연장으로 처리한다.
- `coveragePeriod=ACTIVE`는 갱신·재가입 여부까지 확인된 정상기간이다. `POST_TERMINATION`은 계속 중인 입원임을 확인한 값과 경과일 1~180을 요구한다. 경과일 초과/누락, 조건 false/누락은 확인 요청으로 중단한다. 종료 후 계속 입원에는 `benefitLimitRestored=true`도 누적 보험금을 초기화하지 않는다.
- 입력된 숫자는 사용 분기와 관계없이 유한한 비음수여야 한다. 금액 0 자체는 유효하다. 계약 가입금액은 해당 담보 지급을 위한 양수 한도이며 0 가입금액을 정상 지급 담보로 취급하지 않는다.
- 기존 테스트의 보험금 기대값은 유지했다. 정상 입원 fixture에는 ACTIVE를 명시했다. 기존 “병실료 0원이면 NaN 일수를 무시” 사례는 새 요청의 모든 NaN 차단 원칙에 따라 확인 요청으로 바꿨다. 이는 보험금 산식 변경이 아니라 숫자 입력 검증 변경이다. C06 산식은 만들지 않았다.

## 1704.1 실제 PDF에서 확인한 계산 규칙

기계 판독 가능한 RULE_ID / condition / formula / input_fields / limits / deductible / source_clause / source_page / verification_status는 `samsung-1704-1-rules.json`에 기록한다. 기존 실행 명세 10개 규칙을 재사용하며 운영 JSON은 비활성 상태를 유지한다.

- 기본형 표준형: 제3조, PDF 47~56쪽. 입원 일반 의료비 80%, 병실료 차액 50% 및 일평균 10만원 한도. 일반 자기부담 연200만원 상한. 하나의 상해/질병당 증권 한도 최대 5천만원.
- 기본형 선택형Ⅱ: 제3조, PDF 105~115쪽. 입원 급여90%·비급여80%. 급여10%+비급여20%만 연200만원 상한 기초. 병실료 별도.
- 외래: 의원1만원/병원·일반 종합병원1.5만원/종합전문·상급종합2만원과 정률 공제 중 큰 금액. 처방8천원과 정률 공제 중 큰 금액. 표준20%, 선택Ⅱ 급여10%+비급여20%. 외래/처방 각180회·건, 가입금액 합30만원. 같은 날 동일 상해/질병·목적은 합산하고 의료기관 중 최고 공제를 사용한다(PDF 50/56/109/115).
- 기본형 비건보: 입원 대상액40%, 통원 공제 후40%(PDF 48/51/52/56/106/109/110/115). 비급여만 발생했다고 비건보로 분류하지 않는다.
- 도수·체외충격파·증식: 특약 제3조 PDF165~167. 행위별 max(2만원,30%) 공제, 세 치료 합산 연350만원/50회. 1입원·통원에 복수 행위가 있어도 행위별 계산.
- 주사: 특약 제3조 PDF172~174. 1입원·1통원 단위 max(2만원,30%), 연250만원/50회. 동일 입원 중 주사 여러 건은 합산. 퇴원 당일 동일 상해·질병으로 전원한 입원도 연속 입원. 항암제·항생제(항진균제 포함)·희귀의약품은 기본형으로 분류한다. `VISIT` 단위는 이 계산기에서 확인된 1입원 또는 1통원 묶음을 뜻한다.
- MRI/MRA: 특약 제3조 PDF180~181. 진단행위별 max(2만원,30%), 연300만원. 횟수50회를 임의 적용하지 않는다. 조영제·판독료 포함. 여러 부위 또는 반복 검사도 각각 진단행위 단위.
- 3대 특약에는 기본형의 비건보40% 분기를 복사하지 않는다. 해당 특약 대상 비급여 금액으로 확인한 값을 사용한다.
- 기본형 계속치료: PDF49/53/107/112 입원180일, PDF50/55/109/115 통원180일·90회/90건. 종료 후 입원 한도 복원은 적용하지 않는다.
- 특약 계속치료: PDF167/174/180. 종료 다음날부터180일, 직전 기간 지급액과 횟수를 차감한 잔여 한도를 이어 쓴다. 90회나 한도 리셋을 적용하지 않는다. `priorPaidBenefit`/`priorAnnualCount`는 종료 전 누적+계속치료 중 이미 지급한 누적을 포함해 전달한다.

## 입력 계약과 외부 확인 책임

- `coverageStates`는 `VARIANT_STANDARD`/`VARIANT_SELECTED2` 및 `BASE`/`MANUAL_THERAPY`/`INJECTION`/`MRI`별 CONFIRMED, NOT_ENROLLED, UNKNOWN을 구분한다. UNKNOWN/키 누락은 확인 요청, 확인된 미가입은 NOT_ENROLLED/claim0이다.
- 기존 호출 호환을 위해 `coverageStates`가 없는 경우 `requiredCoverageConfirmed=true`를 현재 규칙의 모든 필요 담보가 확인됐다는 기존 계약으로 해석한다. false/undefined는 계산하지 않는다. 새 호출은 개별 상태를 사용해야 한다. 상태 맵을 주면 기존 boolean으로 UNKNOWN을 덮어쓸 수 없다.
- 임의/미검산 rule ID, 다른 상품 원문, NEEDS_REVIEW 상태는 계산하지 않는다. 현재 허용 상태는 기존 초안의 SOURCE_AND_ENGINE_VALIDATED_RAG_PENDING이며 사람의 운영 승인 VERIFIED를 뜻하지 않는다.
- 의료비 분류·가입·진료형태·동일 사고/질병 묶음·면책 판정과 누적액의 수집은 호출자 책임이다. 함수는 건별 산식 검산기이고 환자/계약/사고ID 또는 날짜 원장을 관리하지 않는다.
- UI에서 아직 받지 못하는 입력: 개별 담보 상태, 병실료 및 정확한 입원일수, 두 통원 가입금액, 담보별 누적 지급액·횟수, 계약종료/계속치료 확인, 특약별 합산 단위, 특약 주사 분류, 검증된 외부 비례계수. 이번에 UI를 추가하지 않았다.

## 면책과 남은 검증

기본형 제4조 및 특약 제4조(PDF57쪽 이후, 168~171/175~178/181~184)를 확인했다. 고의·전쟁·특정 활동/질환, 외모개선·검진 등 비치료 목적, 해외기관, 자동차/산재 보상 등에는 예외 조항도 있어 키워드만으로 자동 제외할 수 없다. `policyExclusionsCleared=true`로 관련 조항과 예외까지 확인된 보상대상 금액만 계산한다. 기본형에는 3대 특약 금액 제외 확인을 별도 요구한다. 면책 전체를 자동 판정하는 코드 구현은 아니다.

C06: 외부 계수의 생성자·계약별 보상책임액 산출/검증 근거는 여전히 NEEDS_REVIEW. 숫자 범위 통과가 약관상 계수 검증 완료를 의미하지 않는다. 원화 소수점 처리와 보험사 지급 관행은 이번 확인 조항에서 확정하지 않았으므로 임의 반올림 규칙을 추가하지 않았다.

운영 연결은 보류한다. 원문 근거가 있는 산식과 검산 테스트, 계약별 증빙/누적·자격 확인, 최종 운영 승인은 별개다.
