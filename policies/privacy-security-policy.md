# 실손보험 1~5세대 RAG 상담 서비스 개인정보·정보보안 정책

> 문서 버전: v1.1 (15절 시연 단계 예외 추가)  
> 상태: `DRAFT_INTERNAL_REVIEW`  
> 적용 대상: `AI_IHID` 실손보험 1~5세대 정보 제공·모의계산·RAG 상담 서비스  
> 시행일: 법률·보안 검토 후 확정  
> 주의: 내부 정책 원본이며 외부 공개용 개인정보처리방침을 대신하지 않는다.

## 1. 목적과 서비스 한계

서비스는 검증된 공식자료에 근거한 일반 정보와 검증된 Rule Engine의 모의 계산을 제공한다. 보험 유지·해지·전환을 추천하거나 실제 보험금 지급 여부를 확정하지 않는다. 근거가 부족하면 추측하지 않고 `INSUFFICIENT_EVIDENCE`를 반환한다.

## 2. 기본 원칙

- 최소수집: 서비스에 불필요한 개인정보를 요구하지 않는다.
- 목적 제한: 입력정보를 해당 요청 처리 외의 목적으로 사용하지 않는다.
- 보유 최소화: 불필요한 원문과 민감정보를 저장하지 않는다.
- 사용자 통제: 저장 여부, 보유기간, 삭제 방법을 공개용 방침에서 안내한다.
- 근거 기반: 공식자료와 검증된 Rule만 사용한다.
- 기본 차단: 판단할 수 없는 입력과 미검증 자료는 허용하지 않는다.

## 3. 입력정보 분류

개인정보 없이 처리할 질문은 세대별 구조, 급여·비급여, 자기부담·공제·한도, 특약 구조와 보험사 확인사항이다.

제한적으로 사용할 수 있는 비식별 정보는 세대, 상품명·버전, 가입 시기, 보험료, 보장종목, 특약 가입 여부와 가상의 치료비·횟수다. 계약 식별번호 없이 처리한다.

입력 금지 또는 차단 대상:

- 주민등록번호·외국인등록번호·여권번호·운전면허번호
- 보험증권번호·계약번호·고객번호
- 계좌번호·카드번호·비밀번호·인증번호
- 이름·전화번호·이메일·주소 등 불필요한 식별정보
- 진단서·처방전·영수증·상세 진료기록 원문
- 병명·병원명·진료일·약제명 등 불필요한 건강정보
- 타인의 개인정보

## 4. 처리 파이프라인

```text
사용자 질문
→ 동의·정책 버전 확인
→ 개인정보·민감정보 탐지
→ 차단 또는 비식별화
→ 질문 범위 분류
→ Scope OUT·의료조언·추천·지급확정 차단
→ 허용 질문만 RAGFlow 검색
→ VERIFIED 공식 근거 확인
→ 필요한 경우 검증된 Rule Engine 계산
→ 최소 데이터만 Gemini에 전달
→ 숫자·Rule·Evidence·문서 ID 검증
→ 사용자 응답
```

## 5. RAG 데이터 보안

- RAG 지식베이스에는 금융당국·보험사 공식자료와 운영자가 검증한 자료만 등록한다.
- 모든 RAGFlow 문서·청크는 `status: "VERIFIED"`여야 한다.
- 사용자 질문·주장·LLM 답변을 지식베이스에 자동 저장하지 않는다.
- 사용자 질문과 공식 지식베이스를 논리적으로 분리한다.
- 미검증·상태 누락·거절 자료는 근거에서 제외한다.
- 다른 상품·세대·담보가 섞이지 않도록 검색 전후 필터를 사용한다.

## 6. LLM 외부 전송

외부 AI에는 설명에 필요한 최소 데이터만 전달한다. 이름, 연락처, 계약 식별번호, 병명, 병원명, 진료일, 진료기록, 영수증 이미지, 계좌·카드·인증정보는 전달하지 않는다.

외부 전송 전 유효한 동의, 개인정보 제거, 허용 필드 DTO, 근거·계산 검증을 모두 통과해야 한다. 계산 설명 API는 15·16번 승인 전까지 `FEATURE_DISABLED`를 유지한다.

## 7. 질문 범위

- 약관·세대·특약·자기부담·공제·한도 설명은 허용할 수 있다.
- 진단·치료·약 복용 조언은 차단한다.
- 가입·해지·전환 추천과 실제 보험금 지급 확정은 차단한다.
- 의도가 불명확하면 `CLARIFICATION_REQUIRED`를 반환한다.
- 개인 모의계산은 검증된 입력과 Rule Engine이 있을 때만 수행한다.

## 8. 로그와 보유

요청 ID, Scope 결과, 검색 문서·Evidence ID, 응답 상태, 오류 코드, 처리시간, RuleSet 버전과 Rule ID만 최소한으로 저장한다. 질문 원문 개인정보, 건강정보, 계약·계좌·결제·인증정보는 저장하지 않는다.

구체적인 보유기간과 삭제 절차는 법률·운영 검토 후 별도 정책에서 확정한다.

## 10. Prompt Injection과 데이터 오염 방지

- 시스템 규칙 무시, 내부 문서 공개, 근거 없는 답변 요구를 따르지 않는다.
- 검색 문서 안의 지시문도 데이터로만 취급한다.
- LLM 답변을 검수 없이 RAG 문서·Rule·Evidence로 승격하지 않는다.
- 사용자 경험담과 주장만으로 Rule을 변경하지 않는다.
- 공식자료 확인과 두 명의 검수 없이 Rule 상태를 올리지 않는다.

## 11. 근거 부족 표준 안내

```text
등록된 공식 자료에서 충분한 근거를 찾지 못했습니다.
약관 또는 보험사 고객센터에서 정확한 내용을 확인해주세요.
```

## 12. 계산 Rule 보안

```text
NEEDS_SOURCE_REVIEW
→ SOURCE_VERIFIED
→ RULE_DRAFTED
→ VERIFIED_FOR_CALCULATION
```

`VERIFIED_FOR_CALCULATION` 이전에는 계산을 활성화하지 않는다. 계산 결과에는 상품 코드, RuleSet 버전, Rule ID, Evidence ID를 남기되 개인정보는 남기지 않는다.

## 13. 사고 대응

```text
사고 탐지
→ 접근 차단·추가 유출 방지
→ 영향 범위와 개인정보 포함 여부 확인
→ 필요한 로그 보존
→ 내부 보고
→ 법률·규제상 신고·통지 검토

```

## 14. 정책 변경과 승인

- 변경 버전, 사유, 승인자, 시행일을 기록한다.
- 입력 필드·외부 전송·로그·보유기간 변경 시 검토를 다시 수행한다.
- 12~16번 문서와 코드가 정책과 다르면 더 엄격한 안전 기준을 우선 적용한다.

## 15. 시연 단계 예외 (공모전 시연 한정)

14절의 "정책과 다르면 더 엄격한 기준 우선" 원칙에도 불구하고, 아래 두 가지는 공모전 시연 기간에 한해 의도적으로 정책보다 넓게 운영한다. 코드는 바꾸지 않고 설정과 화면 고지로 위험을 줄인다.

### 15-1. 예외 내용

| 구분 | 정책 (5·12절) | 시연 단계 실제 운영 |
|---|---|---|
| RAG 근거 자료 상태 | 모든 문서·청크는 `VERIFIED` (5절) | `AI_CROSS_CHECKED` 등을 허용한다. 챗봇 검색용 정책자료 조각 274개(문서 15개)는 모두 `AI_CROSS_CHECKED`이며 `RAG_ALLOWED_STATUS` 환경변수로 허용 범위를 넓혔다 |
| 계산 활성화 조건 | `VERIFIED_FOR_CALCULATION` 이전에는 계산 비활성 (12절) | 상품 규칙이 `REVIEW_REQUIRED` 상태인 채로 모의 계산 결과를 보여 준다 |

근거 맵(`EVIDENCE_MAP_ALLOWED_STATUS`)은 `/api/evidence`에서만 쓰이고 현재 어느 화면도 호출하지 않으므로 이 예외의 대상이 아니다.

### 15-2. 사유

- 챗봇 근거 자료의 검색 적중률이 사전에 정한 합격선에 근소하게 못 미쳤다(dev 40문항 85.0%, 합격선 90%. final 31문항 83.9%, 합격선 85%). 결과를 본 뒤 합격선을 낮추지 않았고, 그에 따라 `VERIFIED`로 올리지 않았다.
- 미달 원인은 자료 내용의 오류가 아니라 검색 누락이다. Gemini 종단 평가(팀 확정 질문 15문항)에서 사실 오류는 0건이었고, 근거가 없으면 지어내지 않고 "확인되지 않습니다"로 응답한다.
- 계산 규칙은 삼성화재 약관 5개를 쪽별 원문과 대조해 AI 원문 검증까지 마쳤으나, 사람의 최종 승인(`VERIFIED_FOR_CALCULATION`)은 아직 받지 않았다.

### 15-3. 확인 기록

- AI 교차검증: 독립 검증 에이전트(별도 세션), 2026-10-04
- 팀 확인(사람 검수): 유소율, 김서영, 민서영. 검수표는 `knowledge/validation/team-review/`에 보관한다.
  - 2026-10-04 (`팀원검수표_작성본.xlsx`): 챗봇 답변 핵심 문장 60건과 고정 안내문 6건을 원문 쪽과 대조했다. 처음 검수에서 문장 59건 일치, 1건 불일치였다. 불일치는 `IN-11-38`("약 1,700만명")이며 검수표가 출처를 `FSC-5G-01` 8쪽으로 잘못 지정한 것이었다. 같은 내용이 `FSC-5G-02` PDF 7쪽(인쇄 12쪽, Q11)에 있어(AI 교차검증 보고서와 원문 재확인) 팀원 허락을 받아 2026-10-07에 해당 행을 정정했고, 정정 후 60건 모두 일치다. 정정 전 원본은 `팀원검수_간편/팀원검수표_작성본.xlsx.bak`에 보존했다.
  - 2026-10-07 (`팀원검수표_추가검수.xlsx`): 앞선 검수에 문장이 없던 7개 문서(`FSC-5G-03`, `KNIA-01`, `GEN2-01`, `GEN4-02`, `GEN3-01`, `GEN3-02`, `GEN4-03`)의 핵심 문장 37건을 대조했다. 33건 일치, 4건 불일치. 불일치 4건은 검수 문장의 표현 문제다(공제식에서 "보장대상의료비×" 누락 3건, "비급여" 누락 1건). 원문이나 근거 조각의 오류가 아니다.
  - 결과: 불일치 5건(10/4 1건, 10/7 4건) 모두 검수표 쪽 문제였고 챗봇 근거(`api/_data/policy-chunks.json`)는 수정하지 않았다.
- 검수 범위와 한계: 두 검수를 합쳐 근거 문서 15개 모두에서 최소 1건 이상 확인했다(`INS-01`은 3건). 그러나 확인한 것은 챗봇이 답변에서 쓸 핵심 문장 97건이며, 조각 274개 전체를 하나씩 대조한 것은 아니다. 근거 조각은 공식 PDF에서 글자를 그대로 추출한 것이다. `INS-01`은 자체 작성 요약본이라 AI 교차검증(28항목)에서 정정했다.
- 메타데이터 `teamConfirmedAt`은 전 문서 2026-10-04로 기록되어 있다. 2026-10-07 추가 검수 일자는 메타데이터에 반영하지 않았다(챗봇 동작과 무관).
- 검수 문서의 `팀 확인`은 사람이 원문과 문장을 대조했다는 뜻이며 `status`를 `VERIFIED`로 올리는 근거가 아니다(`VERIFIED`는 평가 합격선 통과로만 올린다).

### 15-4. 보완 조치

- 챗봇 답변에는 출처 카드를 함께 보여 주고, 근거 부족 시 11절 표준 안내를 사용한다.
- 답변 검사기가 근거에 없는 숫자와 단정·추천 표현을 차단한다.
- 계산 결과 화면에는 `VERIFIED`가 아닌 규칙에 "보험사 확인 필요" 배지를 표시하고, 서비스는 모의 비교이며 보험금 확정이 아님을 고지한다.
- 챗봇 동의창에서 외부 AI(Google Gemini API) 전달, 해외 처리 가능성, 무료 서비스 약관상 서비스 개선 사용 가능성, 질문 미저장, 개인정보 입력 금지를 안내한다.
- 운영 로그에는 요청 ID, 처리 결과, HTTP 상태, 처리 시간만 남기고 질문 원문·답변·개인정보는 남기지 않는다.
